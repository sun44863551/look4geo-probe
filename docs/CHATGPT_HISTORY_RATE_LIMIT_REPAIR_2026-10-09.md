# ChatGPT 对话记录过频限制修复（2026-10-09）

依据：用户截图“请求过于频繁……暂时限制你访问对话记录……请稍等几分钟后再重试”，以及 RUN_S3 批次驱动自动解封记录。

## 本次实现

- 识别 Too many requests、问答过频及对话记录访问限制；启动页发现限制时不发送新问题。
- 运行期间发现限制时，从本次提交前后的回答差值中保留可见正文，排除旧回答和题目回显。
- 限流记录保留 raw_answer 和 conversation_url，但 status=failed、failure=rate_limited、信源采集标为 failed。正文可能未结束，不是有效商业样本。
- 第一次确认限流即停止该平台剩余 repeats。
- 按 ChatGPT 浏览器实例保存本地30分钟冷却，跨 CLI 进程有效；冷却期内不创建浏览器会话。文件位于 data/runs/.chatgpt-cooldown-<实例>.json。损坏冷却记录不自动放行。
- 五个 RUN_S3 驱动取消自动解封、请求间隔由3秒改为30秒，未完成时保留封锁，等待人工确认恢复。其他平台可以继续独立任务，不替换 ChatGPT 账号。

30分钟为保守本地退避，不是平台恢复时间。冷却结束不会自行启动客户任务；批次封锁仍需人工恢复。若仍有限制，新确认的限流将重新建立冷却。

## 本机驱动文件

run_dcta100.sh、run_jp100.sh、run_sku100.sh、run_chatgpt_arm.sh、run_full_600.sh。

修改前副本保存在项目 work/runtime-backup-2026-10-09/（本机忽略目录）。未删除或改写客户样本、SUMMARY.csv、BATCH_STATE.json；未启动或补跑客户任务。

## 恢复流程及边界

1. 保持采样暂停，等待页面所示恢复条件；没有明确恢复时间时不要连续刷新。
2. 恢复后核对原始题目、会话URL及已保存正文，优先人工读取原会话，而不是立即重新提问。
3. 只有正文、题目对应关系、完成状态及信源状态经过复核，才允许建立有效样本。
4. 过去已经保存为空且没有会话地址的样本，本次修改不能逆向重建。不得自动改成成功或未提及。

本次未新增自动历史恢复/自动补跑命令；会话URL是恢复线索，不表示正文已完整，也不表示对话记录限制已解除。30秒间隔仅降低请求压力，无法保证平台不再限流。
