# BrowserSkill 0.4.2 兼容修复（2026-11-06）

## 日志与原因

当天三平台冒烟日志中，ChatGPT/Gemini 先后出现控制权撤销、缺少未使用的严格观测、观测已变化等错误。CLI 与扩展的协议错位已由本机升级消除；当前采样实例 81483588 的扩展为 0.4.2、协议 1.8，与 CLI 0.4.2 匹配。升级后的客户日志只证明三个平台各成功一次，不是每平台 R=3。

本机已有未提交的协议适配、ChatGPT 预填、信源弹层采集改动。本次在其基础上修复两处剩余问题：

1. 形如 `click @e7`、`click <CSS selector>` 的位置参数是 DOM 目标，不应误带整页严格观测。脚本、视觉点击和无目标按键仍用同步返回的顶层观测凭据。
2. 优先识别结构化控制权错误。用户接管、明确停止、动作已应用或效果不明时，不自动重放该动作，也不走输入替代路径。控制权尚未交还时不发送后续输入。

不再默认强制前台聚焦；只为 ChatGPT 的语言注入预先加载站点，其余平台避免启动时重复导航。保留明确的采样实例、Gemini Flash、Perplexity 普通 Search 和原有信源分类口径。

随后验证还发现：成功记录未透传会话链接，CLI 命令超时后未回收自己的子进程。两处均补了回归测试与修复。Gemini、Perplexity 导航改为等待 DOM 就绪，之后仍独立检查输入框和模式，避免等待无关资源拖住导航。

## 同日续修：Gemini 正文与 ChatGPT 链接预览

- **Gemini 模式**：现场确认 3.8 Flash 与 3.5 Flash-Lite 是独立菜单项，角色为 menuitemradio。旧逻辑误把包含 Flash 的 Flash-Lite 当成 Flash。现在精确确认模式；默认仍是 Flash，按用户授权可显式设置 `LOOK4GEO_GEMINI_MODE=flash-lite`。不自动用 Pro 或其他模式替代。
- **Gemini 正文**：两种模式均出现页面提示已回复但旧抽取为空。Flash-Lite 短题诊断确认 `message-content .markdown` 中实际已有 829 字符，节点含 P、OL，而该节点 innerText 为空。修复只对 Gemini 已识别的 model-response 正文节点回退读取 DOM 文本，保留块级换行并排除脚本、样式和 aria-hidden 的子元素。不使用内部 API 或猜测缺失文本。
- **真正空回复**：确认页面已报告完成后，连续四次仍没有正文则报 extraction_failed，不自动重发。没有完成证据的空状态仍按原超时边界处理。
- **ChatGPT 引用**：真实诊断样本证明部分 DIL 弹层是带正文直链的链接预览。仍尝试读取弹层；预览不可读时，仅当对应规范化网址已在正文来源中且未标记额外来源，才视为该链接已采。无直链、标有更多来源或打开异常仍保留部分失败；已抓到的正文来源不丢弃。
- 续修后的完整离线回归为 **408 passed**；无新增 API 或账号切换。

## 实测发现的后续修复

- **Gemini 正文前缀**。首轮 Flash-Lite 采到完整正文与两条网站来源，后两轮错误保留了单字母 `A`，这两条记录判为无效。现场同一正文节点的 `innerText` 只有 1 字符，而 `textContent` 已稳定包含 1,406 字符。现在识别空显示或可见文本只是已存正文前缀的情况，并对提取后的正文执行原来的稳定性检查。保留网页显示完整正文时的格式。
- **ChatGPT 账号状态变化**。第三轮提交后网页出现 `Your account changed. Send your message again`。旧代码等到超时。现在只识别 ChatGPT 的对应告警节点，立即记录发送失败，避免自动重发。前两轮正文已保存，第二轮保留了 4 条链接，另有 4 个引用弹层未解析。第三轮未计作有效样本。
- **ChatGPT 预填导航**。随后一次独立检查卡在预填网址导航、未送出问题。预填现在只等待 DOM 就绪，仍逐字核对输入框，并继续验证提交状态。修复后的独立网页检查取得 2,314 字符正文和 5 条链接，信源状态为 `captured`。
- **ChatGPT 首页与语言校验**。对明确的网页连接关闭只有限重试页面导航。BrowserSkill 若报告动作效果不明，停止当前尝试。应用语言后先等待浏览器确认跳转，再单独检查文档就绪、页面语言、浏览器语言和输入框，避免加载超时被算作采样成功。

## 11 月 7 日续修 ChatGPT 分组引用

- 网页复现区分了两种控件。普通链接预览包含实际 `a[href]`。带 `+N` 的分组引用可以没有直链，弹层内是网页来源按钮。旧逻辑只扫描锚点，无法读取该分组。
- 通过 BrowserSkill 的正常网页操作打开分组和来源按钮，从采样会话新打开的标签页读取实际目的网址。回放核验了 RFC Editor 和 Google 来源。只读采样窗口范围内的标签页，关闭时使用目标标签页自己的控制和观测凭据。遇到明确的关闭权限拒绝，返回已知的原会话标签页，把其余标签页交给会话清理。
- 按分组标出的数量核对来源卡片。没确认的网址留作部分失败，已采网址和正文分别保留。浏览器回执没有弹层数据时继续等待，不把空回执当成已采。分组来源记为正文引用，并保留来源面板的证据归属。
- 指针先在分组上停稳，再用正常点击固定弹层。完成当前分组后收起弹层，再定位下一组。同一个曾有两个分组未解析的长题会话回放通过全部 5 个分组，去重后 3 条网站来源，状态为 `captured`。回放不计作新问答样本。
- 修复后在实例 `81483588` 用常规本机入口新跑 R=3。三轮正文为 2,101、2,544、1,933 字符，链接记录为 3、6、6 条，排除示例域名后实际网站来源为 3、4、4 条。三轮均验证了英文买家语言，信源状态均为 `captured`。本组是常规链接验证，分组覆盖由上述真实会话回放验证。记录保存在 `work/verification-20261107-chatgpt-pinned-r3`。完整回归 421 项通过，最终无遗留 BrowserSkill 会话。
